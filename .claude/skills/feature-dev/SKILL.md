---

새 기능을 구현할 때 아래 단계를 순서대로 진행한다.

## 실행 절차

### Phase 1. 요구사항 확인

사용자의 요청을 분석하고, 아래 항목이 불명확하면 질문 후 진행한다:
- 구현 범위 (프론트엔드만? 백엔드만? 둘 다?)
- 연관된 기존 기능 (어떤 화면/API와 연결?)
- 엣지 케이스 처리 방향

> 명확하면 질문 없이 바로 Phase 2로 넘어간다.

---

### Phase 2. 병렬 코드 탐색

code-explorer 에이전트 2~3개를 **병렬로** 실행한다. 각 에이전트에 다른 탐색 목표를 지정:

- 에이전트 A: "구현할 기능과 유사한 기존 코드 패턴 탐색"
- 에이전트 B: "관련 레이어(컴포넌트/서비스/쿼리)의 아키텍처 탐색"
- 에이전트 C: "관련 타입 정의 및 인터페이스 구조 탐색" (필요한 경우)

에이전트 결과를 받은 후, **핵심 파일들을 직접 Read**하여 컨텍스트를 확보한다.

---

### Phase 3. 설계 & 사용자 확인

탐색 결과를 바탕으로 구현 계획을 작성한다:
- 생성/수정할 파일 목록
- 데이터 흐름
- 주요 설계 결정과 이유

사용자에게 계획을 보여주고 승인을 받은 뒤 구현을 시작한다.

---

### Phase 4. 구현

승인된 계획대로 구현한다:
- 기존 패턴과 컨벤션을 엄격히 따른다
- 한 번에 한 파일씩 완성하고 넘어간다
- 진행 상황을 중간중간 보고한다

---

### Phase 5. 병렬 코드 리뷰

code-reviewer 에이전트 3개를 **병렬로** 실행한다:

- 리뷰어 A: 버그 & 정확성 관점
- 리뷰어 B: 컨벤션 & 가독성 관점
- 리뷰어 C: 보안 & 성능 관점

리뷰 결과를 취합하여 심각도별로 정리한 뒤 사용자에게 보고한다.
HIGH 심각도는 즉시 수정, MED/LOW는 사용자 판단에 맡긴다.

---

### Phase 6. 완료 보고

- 구현한 파일 목록
- 주요 설계 결정 요약
- 수정한 리뷰 항목
- 다음 단계 제안 (테스트 작성, 연관 기능 등)

---

## 빠른 실행 (소규모 작업)

변경 범위가 작으면 (파일 1~2개 수정) Phase 2~3을 생략하고 바로 구현해도 된다.
리뷰는 항상 수행한다.
