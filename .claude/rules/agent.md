# 에이전트 & 병렬 도구 사용 규칙

## 서브에이전트 사용 기준

### 반드시 에이전트를 쓰는 경우
- 탐색할 파일/디렉토리가 3개 이상일 때 → code-explorer 병렬 실행
- 구현 완료 후 코드 리뷰 시 → code-reviewer 병렬 실행 (버그/컨벤션/보안 각 1개씩)
- 테스트 작성이 필요할 때 → test-writer 실행

### 에이전트 대신 직접 처리하는 경우
- 단일 파일 수정
- 명확한 1~2단계 작업
- 빠른 답변이 우선인 질문

## 오케스트레이터 패턴

복잡한 기능 구현 시 아래 순서를 따른다:

```
1. 탐색 (병렬)
   code-explorer A → 유사 기능 패턴 분석
   code-explorer B → 관련 레이어 아키텍처 분석
   code-explorer C → 타입/인터페이스 구조 분석

2. 구현 (직접)
   탐색 결과를 종합하여 구현

3. 리뷰 (병렬)
   code-reviewer A → 버그 & 정확성
   code-reviewer B → 컨벤션 & 가독성
   code-reviewer C → 보안 & 성능
```

## 병렬 도구 호출 규칙

- 독립적인 Glob, Grep, Read 호출은 **항상 단일 메시지에서 병렬 실행**한다
- 예: 여러 파일을 읽어야 할 때 → Read 여러 개를 한 번에 호출
- 예: 파일 검색 + 패턴 검색이 동시에 필요할 때 → Glob + Grep 동시 호출
- 순서 의존성이 있는 경우에만 순차 실행 허용

## 모델 선택 기준

| 작업 | 모델 |
|------|------|
| 코드 탐색, 리뷰, 테스트 작성 | sonnet |
| 아키텍처 설계, 복잡한 리팩터링 | opus |
| 단순 반복 확인 | haiku |

## Context Engineering

- 에이전트에게 지시할 때 **탐색 범위를 명확히 지정**한다 (모호한 지시 금지)
- 에이전트 결과를 받으면 **핵심 파일 목록을 직접 Read**하여 컨텍스트를 확보한다
- 에이전트 간 결과가 충돌할 경우 더 구체적인 근거를 가진 쪽을 채택한다
