# 서비스 안정성 규칙 관리

작업 중 이 프로젝트에서 내린 설계 결정, 겪은 버그, 선택한 패턴을 발견하면 해당 프로젝트의 `.claude/rules/stability.md` 에 기록한다.

## 기록 트리거 — 아래 상황이 발생하면 즉시 기록한다

- 여러 구현 방식 중 하나를 선택했을 때 → 선택한 이유
- 사용자가 특정 패턴을 금지하거나 되돌렸을 때 → 금지 이유
- 예상과 다르게 동작해서 삽질한 부분 → 실제 동작 방식
- 프로젝트 고유의 제약/규칙이 확인됐을 때 → 해당 제약
- 버그 수정 후 **"같은 실수를 또 할 수 있는가?"** 에 YES면 → 원인과 해결 방향

"나중에 기록하자"는 없다. 해당 순간에 바로 기록한다.

## 기록 대상

일반적으로 올바른 구현이 여러 가지일 때, **이 프로젝트에서 어떤 방향으로 결정했는지**를 명시한다.

- 특정 라이브러리/패턴을 선택한 이유 (예: `CopyOnWriteArrayList` 선택 이유)
- 실제로 겪은 버그와 그 해결 방향 (예: SSE emitter 키 충돌 → `token + connectionId` 조합)
- 이 프로젝트에서 금지된 패턴과 그 이유

## 기록하지 않는 것

- 언어/프레임워크의 일반적인 모범 사례 (Claude가 이미 알고 있음)
- 프로젝트와 무관한 범용 지식

## 형식

- **통합 우선**: 기존 섹션에 한 줄로 녹일 수 있으면 새 섹션을 만들지 않는다.
- **간결하게**: 항목 하나는 한 줄 이내. 예시 코드는 꼭 필요한 경우에만 포함.
